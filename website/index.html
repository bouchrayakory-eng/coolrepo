Cloud Resume Challenge (Hybrid Serverless & Containers)

An automated, production-grade web platform backed by Terraform and GitHub Actions.

Frontend Architecture & Challenges

Services Used: AWS S3, AWS CloudFront (OAC), Bootstrap 5, Vanilla JavaScript.

Challenge 1: S3 Public Bucket Exposure & Security
Resolution: Disabled all public bucket access on S3. Created CloudFront Origin Access Control (OAC) so static web assets are accessible exclusively via edge CDN endpoints over HTTPS.
Challenge 2: Cross-Origin Resource Sharing (CORS) & Mixed Content
Resolution: Proxying requests directly to an HTTP ALB from an HTTPS frontend caused mixed-content errors. Routed requests through CloudFront's secondary origin path to serve both static UI and container APIs under a single HTTPS domain.
Backend Architecture & Service Trade-Offs

Services Used: AWS ECS Fargate, ALB, ECR, AWS Lambda, DynamoDB, API Gateway.

Service Selection: ECS Fargate vs. EC2
Chose ECS Fargate over EC2 instances to eliminate server management overhead, OS patching, and capacity planning. Fargate provisions and scales container tasks on demand.
Service Selection: DynamoDB vs. Relational RDS
Selected DynamoDB for visitor tracking due to its single-digit millisecond latency, serverless scaling, and zero base cost compared to maintaining an idle RDS instance.
Challenge: ALB Host Header Drop & 502 Gateway Errors
Resolution: CloudFront forwarded incoming Host headers by default, causing the ALB default listener to reject traffic. Configured custom in Terraform to whitelist only specific request headers.
